============================================================
1. INTRODUCTION
============================================================

The Database Architecture defines the structural foundation of the Dhara
Photography ERP Platform.

This document establishes enterprise database standards that every table,
relationship, index, constraint and future database module must follow.

The database must support long-term scalability, maintainability,
performance and future SaaS expansion.

No database implementation should violate the architecture defined in this
document.

============================================================
2. DATABASE OBJECTIVES
============================================================

The database has been designed to achieve the following objectives.

• Enterprise Grade

• Highly Scalable

• High Performance

• Multi Organization Support

• Multi Branch Support

• Data Integrity

• Audit Ready

• AI Ready

• Cloud Ready

• Future Proof

============================================================
3. DATABASE DESIGN PRINCIPLES
============================================================

The database architecture follows these principles.

Normalization

Avoid duplicate data whenever practical.

Consistency

All tables follow common standards.

Integrity

Foreign Keys enforce relationships.

Performance

Indexes are used where required.

Security

Sensitive information remains protected.

Configurability

Business rules remain configurable.

Maintainability

Future modules can be added without redesign.

7. PRIMARY KEY STRATEGY
============================================================

Every table must have a primary key.

Primary Key Type

BIGSERIAL

Future Ready

UUID support for external references.

Rules

• Every table must contain only one primary key.

• Primary keys must never change after creation.

• Primary keys must never contain business meaning.

• Client Portal

• Mobile Applications

Every business entity may contain both

Internal ID

↓

BIGSERIAL

↓

UUID

• Audit History

• Accident Prevention

============================================================

The database must support ACID compliant transactions.

Transaction Principles

• Atomicity

• Consistency

• Isolation

• Durability

Business operations involving multiple tables must execute within a single
database transaction.

Examples

Booking Creation

↓

Booking Services

↓

Staff Assignment

↓

Equipment Assignment

↓

Advance Payment

↓

Activity Log

If any step fails, the complete transaction must be rolled back.

• Every record belongs to one branch.

• Cross organization data access is prohibited.

============================================================
23. DATA RETENTION POLICY
============================================================

Business information is a valuable asset and must be retained according to
defined business policies.

Retention Guidelines

• Client records should remain available permanently unless legally removed.

• Financial records should be retained for long-term business and audit
purposes.

• Booking history should remain searchable.

• Audit logs should remain protected from modification.

• Archived records must remain recoverable.

Retention periods should be configurable through system settings whenever
possible.
